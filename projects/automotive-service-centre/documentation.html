PROJECT EVIDENCE · OODJ GROUP COURSEWORK

Documentation highlights.

A guided summary of the original 56-page Object Oriented Development with Java report, completed 29 May 2026. The report is a four-person group submission with equal 25% workload allocations.

Java SwingUMLOOPCoursework
FUNCTIONAL DESIGN

Four user roles

The application separates manager, counter-staff, technician and customer tasks into role-specific dashboards. Managers oversee staff, pricing and reports; counter staff coordinate customers, appointments and payments; technicians complete jobs and record feedback; customers review their histories and add comments.

The report documents normal service (60 minutes) and major service (180 minutes), an interval-overlap check that prevents assigning an already-booked technician, and an appointment workflow from PENDING through COMPLETED to PAID.

SOFTWARE ENGINEERING

Object-oriented design

The class model has an abstract User class with Manager, CounterStaff, Technician and Customer subclasses, a Reportable interface, and type-safe enums. FileHandler manages local text-file persistence.

The report relates implementation examples to abstraction, encapsulation, inheritance and polymorphism, including overridden methods, validated setters and interface-based reporting.

ENGINEERING TRADE-OFFS

Documented limitations

This coursework system does not provide concurrent multi-instance data access, a rescheduling workflow, database referential integrity, advanced search, email notifications or persistent sessions. It demonstrates SHA-256 password hashing but is not intended as a production authentication system.
