Smart Healthcare: Arrays vs. Linked Lists.

Comparing two custom C++ approaches to analysing patient records across three healthcare facilities — from sorting and searching to billing, memory use, and measured execution time.

PROBLEM & APPROACH

One dataset, two ways to store it.

This October 2026 group coursework assignment compares fixed-capacity arrays with a custom node-based singly linked list. Both console programs read the same CSV records — 200 each from a General Hospital, University Medical Center, and Community Health Clinic — so the analysis can be compared across implementations.

The programs summarise patient demographics, service use and estimated billing; support sorting by age, visit duration and total medical cost; and evaluate linear, binary and binary-style searching. Both implementations measure comparisons, swaps, elapsed time and approximate memory usage.

MY DOCUMENTED CONTRIBUTION

Linked-list implementation and testing.

The submitted CT077-3-2-DSTR workload matrix assigns me 50% of the linked-list program work and 25% of the documentation/testing work. This was a four-person academic team submission, so I do not claim sole authorship of either implementation.

The linked-list version uses a custom PatientList and dynamically allocated nodes. Its records are examined in demographic, billing, sorting, searching, data-quality and facility-comparison operations.

WHAT WE COMPARED

Algorithm trade-offs.

  • Direct access: an array supports O(1) indexed access; a singly linked list traverses up to O(n) nodes to reach a position.
  • Sorting: both programs use selection sort, which makes 19,900 comparisons for 200 records in the documented experiments.
  • Searching: arrays can use O(log n) binary search once sorted, while linked-list binary-style search still incurs node-traversal overhead.
  • Memory: dynamic linked-list nodes use pointer space beyond the record contents; arrays have simpler contiguous storage but fixed capacity in this implementation.
DOCUMENTED RESULT

Searching and measurement.

For an exact-age lookup in 200 records, the report recorded 200 comparisons with linear search and 6 comparisons with sorted-data search in both implementations. The documented execution times are single experimental observations, not general performance guarantees; creating a sorted copy also introduces preprocessing cost.

LIMITATIONS & REPRODUCIBILITY

Academic prototype, not hospital software.

The assignment uses console-only interaction, sample coursework data and no production database, user authentication or healthcare-grade privacy controls. Its selection sort scales quadratically; the arrays have capacity limits; and performance measurements can vary by machine and run.

The source code has been uploaded to a private team GitHub repository. This public case study intentionally does not expose the repository name containing group members' student IDs. Source access and the original report can be shared with permission.
