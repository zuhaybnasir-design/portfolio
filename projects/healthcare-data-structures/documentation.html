SUBMITTED REPORT · OCTOBER 2026

How the two implementations compare.

A privacy-conscious overview of the 30-page Data Structures Solution Work Documentation submitted for the October 2026 C++ group coursework.

PROJECT SCOPE

Three datasets, six record fields.

The report documents 600 patient records across a General Hospital, a University Medical Center and a Community Health Clinic. The CSV fields are patient ID, age, care type, visit duration, base cost per hour and number of yearly visits. Total medical cost is calculated by multiplying visit duration, hourly cost and visit frequency.

DATA STRUCTURES

Array vs singly linked list.

The array version stores patients in fixed-capacity contiguous storage, giving direct indexed access. The linked-list version implements a custom node type with patient data and a next-node pointer. It can grow dynamically but incurs extra memory overhead and must traverse nodes for indexed access.

SELECTION SORT

19,900 comparisons for 200 records.

Both programs sort by age, visit duration or total medical cost using selection sort. As documented in Section 6.1, sorting 200 items involves 200 × 199 ÷ 2 = 19,900 comparisons, matching the program results. Swaps and elapsed time vary by input order, sort key and computing conditions.

DOCUMENT GUIDE

What's covered in the report.

  • Pages 1–5: Workload distribution, objectives, healthcare datasets, data structures and implementation descriptions
  • Pages 6–22: Console screenshots: loading, menus, demographics, expenditure, sorting, searching and executive dashboard
  • Pages 23–26: Sorting/search performance tables, complexity comparisons, memory estimates and facility results
  • Final sections: Recommendations, limitations, discussion, conclusion, future improvements and references
LIMITATIONS & PRIVACY

Not a deployed healthcare system.

The documentation notes fixed array capacity, linked-list memory overhead, O(n²) selection sorting, variability in timing measurements, and the absence of a GUI, database and healthcare-grade security. This was an academic comparison, not a clinical information system.

The original report includes students' names/IDs and is therefore not posted in full on this public portfolio. Its workload matrix attributes 50% of linked-list programming and 25% of documentation/testing to the portfolio owner; the project remains a group submission.
